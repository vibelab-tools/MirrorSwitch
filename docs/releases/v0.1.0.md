# MirrorSwitch v0.1.0 — Linux MVP

MirrorSwitch v0.1.0 is a Rust terminal tool that detects installed development tools, validates
China-hosted mirror candidates per upstream and tool, compares latency only after compatibility
checks, previews redacted changes, applies them transactionally, verifies through the real client,
and restores failed or explicitly selected transactions.

## Install

Each architecture has a generic archive, deb, and rpm. Download the six packages plus
`SHA256SUMS`, verify with `sha256sum -c SHA256SUMS`, then follow the
[Linux installation guide](https://github.com/vibelab-tools/MirrorSwitch/blob/v0.1.0/docs/install-linux.md).

- x86_64: `mirrorswitch-0.1.0-linux-x86_64.tar.gz`, `mirrorswitch_0.1.0_amd64.deb`,
  `mirrorswitch-0.1.0-1.x86_64.rpm`
- arm64: `mirrorswitch-0.1.0-linux-arm64.tar.gz`, `mirrorswitch_0.1.0_arm64.deb`,
  `mirrorswitch-0.1.0-1.aarch64.rpm`

## Supported environment

- Linux `x86_64` and arm64 hosts and containers.
- Required release coverage: Debian/Ubuntu, Fedora/Rocky/AlmaLinux/CentOS Stream, Arch Linux or
  Arch Linux ARM, openSUSE, and Alpine. Gentoo, Void, Nix/Guix, Flatpak, and opkg are extended
  adapter scopes with explicit compatibility rules.
- Terminal frontends: CLI, versioned JSON configuration, and interactive TUI, all backed by the
  same normalized plan.
- 64 supported adapters covering system package managers; Python, Node.js, JVM, Go, Rust, Ruby,
  PHP, .NET, Haskell, Perl, R, TeX, Dart/Flutter, Julia, OCaml, and Emacs ecosystems; container,
  Kubernetes, CI, database, observability, server, and storage repositories.

The exact per-tool scopes, public verification boundaries, and known limits are in the
[adapter reference](https://github.com/vibelab-tools/MirrorSwitch/blob/v0.1.0/docs/adapter-reference.md)
and [support matrix](https://github.com/vibelab-tools/MirrorSwitch/blob/v0.1.0/docs/support-matrix.md).

The binary embeds this catalog. Online runs attempt the GitHub Raw copy with strict validation and
fall back to a valid cache or the embedded baseline. The repository is private at publication
time, so anonymous Raw requests return 404; `status --json` records that fallback. `--offline`
skips the request explicitly.

## Safe use and recovery

Run `mirrorswitch detect`, `plan`, or `status` first. Non-interactive changes require
`mirrorswitch apply --yes`. Plans show target paths, redacted old/new digests, permissions,
service impact, candidate compatibility, selected provider, and latency. System writes require an
already elevated shell; v0.1.0 never restarts a workload service automatically.

Every applied adapter returns a transaction ID. Restore one exact snapshot with:

```bash
mirrorswitch restore TRANSACTION_ID --yes --json
```

## Known limitations

- macOS, Windows, desktop GUI, web UI, and tray applications are not included.
- Conan, Docker daemon registry mirrors, Helm, Jenkins Update Center, and ROS 2 remain `planned`:
  the six-provider scope does not currently expose the complete, signed, architecture-compatible
  content required by their acceptance criteria.
- Project, site, and environment scopes are opt-in. Private sources, credentials, lock files,
  trust settings, database data, cluster workloads, and service configuration outside the exact
  adapter target remain untouched.
- External mirror availability can change after release. A candidate that fails compatibility or
  content probes is skipped instead of being forced into configuration.
