# MirrorSwitch v0.2.0 — macOS and Windows

MirrorSwitch v0.2.0 extends the Rust CLI, versioned configuration file, TUI,
per-upstream mirror selection, transactional apply, verification, and explicit
restore model from Linux to native macOS and Windows environments.

## Release assets

The tag workflow builds each binary on its matching native runner, exercises it
before and after packaging, and publishes those tested bytes without rebuilding
them in the release job.

- Linux x86_64: generic archive, deb, and rpm.
- Linux arm64: generic archive, deb, and rpm.
- macOS 14+ Intel x86_64: tar.gz archive.
- macOS 14+ Apple Silicon arm64: tar.gz archive.
- Windows 10/11 x86_64: ZIP archive.
- Windows 11 arm64: ZIP archive.
- `SHA256SUMS` covers all ten platform files.

See the [macOS and Windows installation guide](https://github.com/vibelab-tools/MirrorSwitch/blob/v0.2.0/docs/install-macos-windows.md),
[Linux installation guide](https://github.com/vibelab-tools/MirrorSwitch/blob/v0.2.0/docs/install-linux.md),
and [support matrix](https://github.com/vibelab-tools/MirrorSwitch/blob/v0.2.0/docs/macos-windows-support-matrix.md).

## Native adapter coverage

macOS includes Homebrew, Nix, CocoaPods, MacPorts, NuGet, and the verified
cross-platform language/runtime adapters listed in the support matrix. Windows
includes WinGet, Scoop, MSYS2, Cygwin, NuGet, host/WSL isolation, and the
platform-applicable cross-platform adapters. Each supported adapter has an
independent closed Issue and native workflow covering detection, a read-only
plan, CLI/config/TUI equivalence, real client verification, idempotency, and
restore. Unsupported architectures return a reason and no plan.

The catalog remains data-only and updates from the repository's GitHub Raw URL.
Remote data cannot add executable adapter or recovery logic.

## Recovery

Review a plan before applying it and retain the transaction ID returned by the
JSON result:

```text
mirrorswitch apply --config request.json --yes --json
mirrorswitch restore TRANSACTION_ID --yes --json
```

File adapters restore recorded bytes and platform attributes. Command-managed
adapters such as WinGet restore external source state through the adapter before
the private recovery record is rolled back. Receipts are user- and host-local;
do not copy them between macOS, Windows, WSL distributions, users, or machines.

## Known boundaries

- macOS archives are not Developer ID signed or notarized. Verify SHA-256 before
  following the documented quarantine procedure.
- GitHub does not provide a Windows 10 hosted runner. The Windows x86_64 build
  uses Rust's Tier-1 Windows 10+ MSVC target and explicit tool-version boundaries;
  Windows 10 arm64 is not a release claim.
- A supported mirror may cover package metadata while an upstream package still
  references external source or installer assets. The adapter-specific contract
  states that boundary and never disables TLS, signature, or checksum checks.
- Chocolatey Community and PowerShell Gallery have no complete compatible feed
  among the six reviewed providers, so v0.2.0 does not expose adapters for them.
- nvm-windows and pyenv-win are different tools from the Unix nvm/pyenv adapters.
- This release is a terminal product only; it does not include a desktop GUI,
  tray application, or web UI.
